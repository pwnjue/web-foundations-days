# Reflection

The most difficult concept in the course was understanding system design, especially how to design an application that can continue working when many users access it at the same time. At first, concepts such as load balancing, caching, databases, transactions, and queues seemed separate and difficult to connect. I overcame this by breaking a system into smaller components and thinking about what each component is responsible for. The TicketHub exercise helped me understand how these components work together, particularly how transactions and database constraints can prevent two customers from buying the same seat.

One part of my capstone that I would improve is the system design and scalability section. Based on the feedback I received, I would make the architecture and handling of high traffic more explicit. I would also explain more clearly how the application would behave when many users access it simultaneously and how failures could be handled.

Next, I want to learn more about cloud computing, APIs, databases, and deployment. I would especially like to learn how to deploy a real web application and use cloud services for scaling, monitoring, and security. I also want to improve my understanding of backend development so that I can build systems that are not only functional but also reliable and able to support many users.
